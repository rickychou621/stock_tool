# Codex 任務：實作 stock_tool 階段二 — 歷史戰法回測與績效驗證

請直接在目前 `stock_tool` 專案完成階段二功能、資料庫變更及測試。**先檢查現有程式碼與階段一實際完成情況，再沿用既有架構實作；不要只提出設計，也不要擴充階段三。**

## 1. 開發前要求

- 檢查 FastAPI、React、MySQL、Docker Compose、FinMind 同步服務、`RuleEvaluationService`、觀察清單及既有 Migration。
- 保留未提交的 Git 修改與現有功能；不要自行 commit、push 或清除既有資料。
- 重用既有戰法計算邏輯；不得為回測另寫一套不一致的戰法判斷。
- 若某戰法尚未完整支援歷史計算，清楚回報限制，不得假造回測結果。

## 2. 回測範圍與啟動方式

- 新增獨立「戰法回測」頁面。
- 回測範圍：**目前觀察清單股票**；預設最近 **3 年**。
- 可勾選回測戰法，預設所有已啟用戰法；與階段一排程戰法設定互不影響。
- 使用者按「執行回測」後，由 Backend 背景執行；不加入每日 18:00 排程。
- 同時間僅允許 **1 個回測任務**，前後端都需防止重複啟動；不建立任務佇列。
- 股票固定 **3 檔並行**；各工作單元獨立資料庫 Session，單檔失敗不阻塞其他股票。
- 切換頁面或關閉瀏覽器不會中止任務；Backend 重啟時，未完成任務標示「已中斷」，不自動續跑，使用者可重新手動執行。

## 3. 行情資料與歷史訊號

- 優先使用 MySQL 現有日K、股利與還原股價；檢查資料完整性，**缺少時才呼叫既有 FinMind 同步服務補齊**，不要每次重抓全部資料。
- 回測最近 3 年，並取得各戰法計算指標所需的前置歷史資料。
- 上市不足 3 年的股票可用實際可取得期間回測，顯示實際起訖日；若仍不足以計算指標，記錄失敗原因。
- 逐日回算戰法「首次符合／持續符合／失效／再次符合」；不可使用當時尚未可得的資料或未來行情判斷當日訊號，避免前視偏差。
- 使用專案既有還原股價機制，確認調整基準一致，避免未來資訊滲入訊號、或股利重複計算。

## 4. 交易模擬規則

- 每個「股票 × 戰法」同時間最多一筆持倉；首次符合時觸發買進，持續符合不加碼；失效時觸發賣出，完成賣出後才可再次進場。
- 訊號於當日行情完成後成立；**下一個有效交易日開盤價**模擬成交（買賣相同）。
- 如預定交易日停牌、開盤價無效或成交量為 0，順延至該股票下一個有效交易日；回測結束前仍無法成交者標示未成交，不捏造價格。
- 進出場使用一致的還原價格基準；**不計手續費、交易稅、滑價，也不額外模擬股利再投入**。
- 回測結束仍持有的交易標示「持有中」，依結束日還原收盤價計算未實現報酬；不計入已完成交易勝率或已實現績效。
- 不同戰法各自獨立持倉及計算。

## 5. 績效指標

依「戰法整體」及「個別股票 × 戰法」兩層級統計：

- 已完成交易次數、勝率（正報酬交易數 ÷ 已完成交易數）。
- 平均單筆報酬率。
- 複利累積報酬率：`PRODUCT(1 + 單筆報酬率) - 1`。跨股票複利僅為比較指標，不宣稱是實際投資組合績效。
- 最大回撤：依已完成交易時間序列的複利績效計算；不含持倉期間浮動損益，標示此限制。
- 獲利因子：獲利交易報酬率總和 ÷ 虧損交易報酬率絕對值總和；無虧損時顯示「無虧損」，避免除以零。
- 已完成交易少於 **10 筆**時標示「樣本不足」，仍顯示所有數據；整體與個股分別判斷。
- 顯示實際回測期間，避免不同長度樣本被誤認為同條件。
- 沒有已完成交易時，勝率等無法計算的指標顯示「無資料」，不要顯示虛假的 0% 勝率。

## 6. 資料保存與部分失敗

- 儲存最近一次回測任務狀態、處理進度、統計與交易明細；不保留每次回測的完整歷史版本。
- 新結果成功產出後取代對應舊結果；失敗股票保留上次成功結果並標示「過期」。
- 允許部分成功，顯示成功數、失敗數與個別錯誤原因；**本次整體績效僅統計本次成功回測股票**，不得混入過期結果。
- 任務意外中斷時標示中斷並保留既有有效結果。
- 保證更新結果與統計的一致性，避免讀到半套交易明細或將失敗結果當成成功。

## 7. 前端介面

獨立「戰法回測」頁面至少包含：

- 戰法勾選及「執行回測」按鈕。
- 執行狀態、已完成／總股票數、成功／失敗數、錯誤資訊。
- 執行中每 **3 秒 Polling** 取得進度；完成、失敗或中斷後停止；重新進頁時可恢復查看任務狀態。
- 戰法整體與個股績效表格、樣本不足標記。
- 逐筆交易明細：股票、戰法、買賣日期與價格、持有交易日數、單筆報酬率、已完成／持有中／未成交狀態。
- 可依股票、戰法篩選，依勝率、交易次數、平均報酬率排序。
- **不做圖表、不做 CSV／Excel 匯出**。

## 8. 驗收與測試

請補充自動化測試並執行專案現有測試、Lint、Build（依專案工具），至少驗證：

1. 歷史訊號不使用未來資料；首次符合、持續、失效、再次符合正確。
2. 下一有效交易日開盤成交、停牌／零成交量順延、未成交處理正確。
3. 一組股票與戰法僅有一筆持倉；未平倉不混入已實現績效。
4. 勝率、平均報酬、複利累積報酬、最大回撤、獲利因子及少於 10 筆標記正確。
5. 未滿 3 年股票可使用實際期間；歷史不足時正確報錯。
6. DB 優先、缺資料才補 FinMind；測試使用 Mock，避免大量真實 API 呼叫。
7. 同時僅一個回測任務、固定 3 檔並行、單檔失敗隔離。
8. 部分成功、過期標示、整體績效排除舊結果、重啟後中斷狀態正確。
9. 前端 Polling、重新進頁、篩選排序及既有功能正常。
